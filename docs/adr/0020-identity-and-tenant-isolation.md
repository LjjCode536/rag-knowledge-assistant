# ADR-0020: 主体身份与租户硬隔离;租户由服务端注入而非调用方声明

**Status**: accepted

## Context

系统此前只在**数据结构**上支持多租户,不保证多租户:

- 租户是知识库文档与切片的普通字段,上传时缺省 `default`;
- 检索与问答的过滤条件 `filters` 是可选参数,`tenant` 为 `None` 即放行全库 —— 任何调用方省略它就能看到所有租户的数据;
- 文档清单、详情、解析产物、切片、向量化、删除、查询日志、反馈与统计都不带主体,不区分调用方;
- ADR-0015 与 AGENTS.md 明确写着"没有用户、没有会话、没有鉴权",前端因此不做登录,也不假装隔离。

结论:这是"打了标签",不是"隔离"。本 ADR 引入身份与强制授权范围,把租户从元数据升级为边界;文档级授权见 ADR-0021。

## Decision

1. **身份载体是短期 JWT。** 生产路径校验 OIDC/JWKS(对接企业 IdP),本地演示由后端签发,种子账号口令用 argon2 哈希。claims 至少含 `sub / tenant / role / department / exp / iss / aud`。不信任请求体或查询参数里的任何身份字段。主体仓储在 pgvector 模式落 `principals` 表,内存模式用种子夹具;OIDC 模式只信 claim,不落本地用户表。
2. **主体与角色。** 主体(Principal)分用户与服务账号,主体唯一归属一个租户。租户内角色 `member` / `admin`;跨租户只有 `platform_operator`。服务账号在 v1 只建模、不提供签发入口。
3. **租户与部门只来自 token。** 上传、检索、问答、清单、日志、统计的请求契约删除 `tenant`(请求模型 `extra="forbid"`,携带即 422);部门同样不再由上传表单自由填写。
4. **授权范围(Scope)是必填参数。** 现有 `ChunkFilter` 收编为服务端内部构造的授权范围,不保留 `None` 默认值;服务与仓储层的每个读写入口都以必填参数接收它,路由依赖只负责把主体解析成 Scope。漏传是程序错误,不是"查全库"。
5. **每条路径都强制收敛。** 检索、问答、文档清单与详情、解析产物、切片、向量化、删除、查询日志、反馈、统计、诊断全部按 Scope 过滤。未携带或无效凭证返回 `401 UNAUTHENTICATED`。客户端可以收窄(部门、文档类型、文档集合),但必须是授权范围的子集;越界返回 `403 SCOPE_VIOLATION`,不静默裁剪。
6. **对象级鉴权返回 404。** 跨租户或不存在的对象一律 404,不泄露存在性;只有显式越界请求才返回 403。
7. **非文档资源的所有权。** `member` 只能读自己的查询日志、只能对自己的 `query_id` 提交反馈;`admin` 可读本租户全部。
8. **角色边界。** `member` 可检索、问答、上传并管理自己的文档、提交自己的反馈;`admin` 另可管理本租户全部文档与写路径、授予/撤销文档授权、查看统计、查询日志、差评候选与诊断;`platform_operator` 是唯一可跨租户的主体,仅在管理端点用显式 `tenant` 参数切换,每次成功访问都写审计。
9. **答档缓存以授权后的范围作键。** 授权或文档生命周期变化即整体清空缓存,避免撤销授权后仍被引用。
10. **审计。** 新增审计事件:越权拒绝、平台管理员跨租户访问、文档授权授予/撤销、文档删除。`query_logs` 与 `feedbacks` 增加显式的 `tenant` 与 `principal_id` 列,统计据此收敛。变更类操作的审计与业务写同一事务(审计失败即请求失败);越权拒绝的审计尽力而为,不改变响应。
11. **公共面收窄。** `/health` 保持公开,只留存活与粗粒度依赖状态;缓存命中率、向量身份盘点等诊断信息移到 `admin` 才能访问的诊断端点。
12. **前端呈现真实边界。** 增加登录页,删除租户切换器;token 存内存 + `sessionStorage`(演示级,生产应换 OIDC + PKCE + BFF/HttpOnly)。ADR-0015 中"后端没有用户、没有会话、没有鉴权"的条款由本 ADR 取代,其余(独立前端工程、零 CORS、proxy、类型手写)继续有效。

## Considered Options

- **可信网关注入身份头**:最轻,但 API 一旦直连即可伪造,本地演示也没有可信网关;放弃。
- **自建账号密码 + 服务端会话**:前端体验完整,但要自己实现注册、改密、会话与 CSRF;口令与签名仍要引库,收益不抵成本;放弃。
- **纯 API Key**:适合机器调用,不适合人类登录与按人审计;放弃。
- **租户作为可选过滤参数**:正是本 ADR 要消除的形态;放弃。

## Consequences

- **破坏性变更**:请求契约删除 `tenant`,`filters` 不再是公开的权限入口;前端、脚本与既有测试同步改写。存量数据全部落在种子租户 `default` —— `default` 从此只是一个租户 id,不再代表"缺省行为",不做数据搬迁。
- **不提供 `AUTH_MODE=off`**:关闭鉴权的开关就是把洞原样装回去;本地开发靠种子账号登录,测试用依赖覆盖而不是绕过。
- **不做数据库 RLS**(本轮):连接池没有请求级事务,`SET LOCAL` 需要改造全部查询路径;应用层强制先行,RLS 记为后续加固的可选项。
- **不做租户生命周期与配额**:租户由身份提供方管理,本系统不建租户注册表,也不做配额与限流(显式出界)。
- **评估不经过 HTTP 鉴权**:评估器在进程内按语料租户构造 Scope;"无过滤对照"只存在于评估模块内部,禁止 `EVAL_BYPASS` 或任何 HTTP 后门。鉴权由测试矩阵证明,检索指标不由鉴权背书。
- **演示级 token 存储**:`sessionStorage` 方案可被 XSS 读取;这是为了本地可演示的取舍,生产必须换成 OIDC 授权码 + PKCE 与 HttpOnly 会话。
