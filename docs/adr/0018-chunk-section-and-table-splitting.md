# ADR-0018: 切分按标题分节;超大表格按行组切;标题只进切片元数据

**Status**: accepted

## Context

对照《02-Chunk切分》逐项比较后,项目与规范有三个值得处理的差异:标题文本没有进入切片内容、超大表格整表保留可能超过向量模型输入、切片记录没有保存产生它的策略。

其中"标题进正文"是规范明确要求,但它会改变切片的 embedding 文本。项目已有黄金数据集与两条评估口径(无密钥确定性替身 / 真实 bge-m3),因此先用同一数据集比较三种行为:

| 方案 | 无密钥 Recall@3 / MRR / NDCG | 上游 Recall@3 / MRR / NDCG | 无密钥引用准确率 |
| --- | --- | --- | --- |
| 改前基线 | 0.7917 / 0.7500 / 0.7609 | — | 0.6377 |
| 分节 + 标题进正文 | 0.7917 / 0.7292 / 0.7455 | 1.0000 / 0.9583 / 0.9692 | 0.5625(跌破 0.60 门禁) |
| 分节 + 标题仅元数据 | 0.7917 / 0.7500 / 0.7609 | 1.0000 / 0.9792 / 0.9846 | 0.6377 |

"标题处断开"本身不改变指标;"标题文本进正文"在确定性替身与真实 bge-m3 上都没有收益,还压低引用准确率。规范是参考最佳实践,不是本项目的硬验收标准,因此选择"分节 + 标题仅元数据"。

## Decision

- `heading` 与 `table_aware` 都以 `TITLE` 元素为硬边界:一节散文单独切,切片不横跨多节;节标题写入切片 `title` 元数据,不拼进正文。
- `table_aware` 遇到超过 `chunk_size` 的表格时按行组切:首行视为表头,每块重复表头;单行数据不切断。表格 / 代码仍是原子结构,不被字符级硬切。
- `Chunk` 增加可空 `strategy` 字段,由 `ChunkingService` 在装配时写入;`chunks` 表增加可空 `strategy` 列(幂等 `ALTER TABLE` 补列,历史切片保持 NULL)。API、前端与向量快照暂不暴露该字段。

## Consequences

- 无密钥门禁与改前完全一致(`0011` → `0012`:Recall@3 0.7917 / MRR 0.7500 / NDCG 0.7609,引用准确率 0.6377);上游 bge-m3 上分节 + 元数据方案略优于标题进正文。
- 标题仍可通过 `title` 元数据用于引用与排障;若将来要让它参与检索,优先在 embedding 输入层拼标题,而不是改切片正文。
- 历史切片与向量快照的 `strategy` 为 NULL,无法反推;新切片始终有值。
- 单行超长表格仍可能超过 `chunk_size`,由 `CHUNK_TOO_LONG` 告警暴露,不做行内切断。
- 规范中的 `min_chunk_size` 丢弃短块、重复切片率校验、按 `doc_type` 预设参数与另外五种策略仍未采纳,留给后续评估驱动迭代。
