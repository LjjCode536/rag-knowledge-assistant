# ADR-0006: 高级检索管线:混合检索、重排薄适配器与数据驱动开关

**Status**: accepted

## Context

T06 之后单向量检索的天花板已见:Recall@3 = 0.7917 / MRR = 0.7500,词法口径外的口语化问题发芽即失。教材第 43 章的生产替换清单给出完整链路(改写 → 多查询 → 混合检索 → 重排 → MMR),但每一步都是开销与收益的权衡,不能一口气全开。需要先定:

1. **各能力的开关位置**:哪些开关放在配置层、各默认值依据什么。
2. **关键词通道的零件来源**:ADR-0001 只允许在 `app/integrations` 用成熟组件作零件,自写轮子仅限重排薄适配器。
3. **重排失败语义**:在线检索不该因增强能力挂掉而 503,但评估报告也不能拿降级数据冒充真实重排。
4. **评估可比性**:消融矩阵与 T06 基线必须逐字同口径,`evaluate.py` 默认口径不能随应用默认值漂移。

## Decision

- **管线与开关**:`RetrievalService` 内部五段——查询改写、多查询扩展、混合检索(向量 + 关键词通道 + 加权融合去重)、重排、MMR——各有 `use_*` 配置开关(T07 用消融数据回填默认值)。全关时退回 T06 单向量时序:一次 embed、一次检索前过滤的 top-k 检索,分数逐字一致,保证基线可复现。问答编排与查询日志字段不变(ADR-0004)。
- **候选池前置**:重排 / MMR 需要 `candidate_k`(默认 30)≫ top-k 的候选池;权限过滤仍全部发生在打分之前,两条通道共用同一份 `ChunkFilter` 契约。
- **关键词通道**:新领域契约 `KeywordIndex` + 内存实现 `InMemoryKeywordIndex`;打分用 `rank_bm25` 的 BM25Plus(小候选集下 Okapi 的 idf 会退化,Plus 恒正),分词与确定性向量替身同口径(`app/domain/lexical`)。融合分 = 各通道 min-max 归一分按权重的固定分母加权(缺失通道记 0 分),避免单通道命中被分母放水。
- **重排薄适配器**:全项目唯一自写轮子 `SiliconFlowReranker`,只做「候选内容报送统一客户端 → 上游 index 还原 → 失败降级」三件事;重试、超时、错误映射都留在统一 LLM 客户端。上游任何失败(限流 / 超时 / 不可用 / 响应坏形)降级回退融合序并留 `retrieval_rerank_degraded` 告警——在线检索不中断。
- **查询改写与多查询扩展**:一个 chat 调用同时产出改写与变体(结构化 JSON),解析失败或上游失败一律回退原查询并留 `query_plan_degraded` 告警;多查询变体与原查询合并成一次批量 embed,逐路检索后按「同一切片取最好分」融合。
- **评估纪律**:`scripts/evaluate.py` 的消融矩阵(A 全关 → G 逐能力叠加)在同一数据集 / K / 切分 / 向量替身上重跑,报告出与 T06 的差值表;重排 / LLM 组合无密钥时**跳过并标注**,绝不拿降级数据混淆报告;评估默认口径固定全关(与 T06 同口径、CI 可复现),要量应用默认值时显式 `--use-app-defaults`。上游调用一律逐个用例串行。

## Consequences

- **收益**:开关矩阵让每个能力对 Recall@K / MRR 的边际贡献可测;默认值有数据依据;重排 / 规划故障不影响在线可用性;基线复现性不随应用配置漂移。
- **代价**:高级路径一次检索最多付出「1 次 chat(LLM 规划)+ 1 次批量 embed + 1 次重排」的上游调用;BM25 小候选集打分对超长切片偏置敏感,换生产关键词引擎(如 pgvector 配套 tsvector)时替换 `KeywordIndex` 实现即可;重排分数与余弦分数分布不同,`qa_min_score` 的阈值语义随重排开关变化,若拒答正确率下降必须在报告里单独论证。
- **实测教训(T07 消融 B 组合)**:混合检索不搭配重排时,融合归一分会把无关暖点抬过拒答阈值(拒答正确率 0.0000)。「混合必须搭配重排校准分数」因此进入默认组合论证;只有重排在链路尾端时,分数才重新具备与 `qa_min_score` 可比的分布。单候选 / 同分候选通道不做归一(原分透传),避免无判别力分数被抬成满分。
- **后续**:MMR 当前默认关闭(消融中挤掉更好的重排序);T08 换真实 LLM 生成器后,重排候选池大小可用生成指标反推;T13 迁移向库 / 关键词索引到生产形态时,`VectorStore` 与 `KeywordIndex` 契约不动。
