# ADR-0005: 评估基座:锚点定位、API 主缝与无密钥检索指标

**Status**: accepted

## Context

T06 需要一条可重复的评估基线,回答"这次改动到底有没有用"。三个现实约束必须先定:

1. **切片 ID 不稳定**:每次上传都会生成新的文档 / 切片 uuid。黄金数据集若写死 `chunk_id`,每跑一次就要改一次数据集,无法作为长期准绳。
2. **评估必须测用户实际走的路**:如果评估器直接调服务层或向量库,测到的是"内部实现",而不是 HTTP 契约、校验、信封与过滤时机。
3. **CI 没有密钥**:检索指标本身不需要生成模型,但向量化仍走上游 embedding。没有密钥时,评估器不能停摆。

## Decision

- **版本化 YAML + 锚点定位**:黄金数据集 (`evaluation/golden_dataset.yaml`) 由语料清单与用例清单组成。预期切片用「文档名 + 文内唯一锚点」声明,评估器在语料入库后把锚点解析成真实 `chunk_id`;锚点命中 0 个或多个都直接失败。切分参数变化不会让数据集漂移,随机 uuid 也不入库。
- **评估器走 HTTP 主缝**:上传 → 切片 → 向量化 → 检索全部调用 `/api/v1/*`。主接缝上的校验、信封、检索前过滤与排序行为与真实用户一致;服务层内部结构可自由重构。
- **无密钥模式是一等公民**:默认在进程内启动应用,注入 1024 维确定性词面向量替身(`bge-m3` 也是 1024 维,降低哈希碰撞噪声),不触网、不计费。报告显式记录 `embedder` 与 `mode`;真实上游模式通过 `--embedder upstream` 或 `--base-url` 运行,不与替身基线混比。
- **指标口径**:Recall@K / MRR / NDCG@K / HitRate@K 只对可回答用例求均值;拒答用例单独按 `qa_min_score` 计算"无高分命中即正确拒答";权限用例检查 top-k 中是否出现 `forbidden_documents`,并额外跑一次**无过滤对照**,证明禁读切片确实会被检索到,权限通过不是因为语料无关。
- **报告双格式**:`docs/iterations/` 下同时落 Markdown(人读)与 JSON(CI / 后续对比)。JSON 带 `schema_version` 与稳定字段名;Markdown 逐用例列出预期锚点、`文档#index`、top-k 命中、逐项指标与结论。`chunk_id` 每次入库随机,只在运行内参与计算、不写入报告;跨运行对比固定「文档 + index + 锚点」,因此重跑只应在真实指标变化时产生 diff。

## Consequences

- **收益**:T07 的混合检索 / 重排消融、T09 的 CI 门禁都消费同一份 JSON;数据集与指标口径不随切分参数或 uuid 漂移。无密钥 CI 能跑出完整检索报告。
- **代价**:确定性词面替身只验证检索编排与词面召回,不能代表真实 `bge-m3` 的语义能力;报告中的 Recall@3 不是生产语义质量的最终结论。需要真实基线时显式跑上游模式并注明 embedder。
- **后续**:T09 在同一数据集上增加忠实度 / 引用准确率 / 拒答正确率与 CI 阈值;新增报告在 `docs/iterations/` 递增编号并附「基线 vs 本次」差值表。若未来改用稳定 document_id,锚点机制仍可保留,只替换解析层。
